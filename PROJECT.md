## Текущее состояние

Приложение работает и опубликовано. Данные владельца чистые: 7 проектов со значками,
7 задач-примеров с исходными оценками, касаний нет, длина дня 8 часов.

**Модель.** Проекты (+`emoji`, `cooldown_days` по умолчанию **2**), задачи,
настройки (`settings.day_hours`). Три таблицы в Supabase, RLS включена на всех,
проверено функционально: анонимный ключ без входа отдаёт 0 строк.

**Экран «Пульс».** Список проектов по зонам жизни:
🟢 В работе · ⚠️ На грани · 💀 Кладбище · 🌱 Ещё не начаты.
В каждой строке инфографика смертей: 21 столбик закрытых часов и непрерывная линия
жизни, где красные участки — периоды, когда проект был мёртв, плюс счётчик «💀 N».
Строка проваливается вниз сама (700 мс с разгоном) и всплывает наверх (420 мс
с торможением). Справа колонка «Сегодня» с заполнением дня против длины дня.

**Экран «Проект»** — задачи по статусам, настройки бюджета и порога, история по неделям.
**Экран «Неделя»** — семь дней, распределение внимания по проектам, общая ось с бюджетами.

**Правка задач.** Время, срок и важность правятся прямо в строке; время принимает
тот же язык, что и быстрый ввод («90», «90м», «1,5ч»).

**Подсказчик** в развороте строки — правила по своим данным, не языковая модель.
Разбирает состояние проекта и предлагает следующий шаг одной кнопкой.

**Хранилище.** Локальный кэш + очередь в облако, индикатор состояния — линия под шапкой.
Вход по magic link на `gorbatovroman86@gmail.com`.

**Копии.** Ночной workflow в 20:00 UTC (03:00 Нск) складывает срез в приватный репозиторий.
Формат версии 2 (включает настройки). Восстановление `npm run restore -- <файл>`
проверено на живых данных, идемпотентно.

Конкретно проверить два места, которые пока не проверялись на объёме:

2. Зона «На грани» при пороге 2 дня — не окажется ли она почти всегда пустой
   (проект прыгает из «В работе» сразу в «Кладбище»).

## Открытые вопросы

- **Почта на бесплатном тарифе Supabase:** 2 письма в час, шаблон менять нельзя,
  кода в письме нет — только ссылка. Проверено запросами к API, оба отбиты сервером.
  Лечится своим SMTP: тогда появятся и коды, и нормальный лимит. Нужны данные SMTP.
- **Настоящая языковая модель для подсказчика** требует прокси-функции на Supabase
  и ключа. Интерфейс подсказок под это уже готов.
- **`BACKUP_PAT`** в секретах репозитория — это токен `gh` владельца.
  Стоит заменить на fine-grained PAT только под `pulse-planner-data`.
- Первый заход по magic link даёт разовый 401 в консоли (обмен токена);
  на работу не влияет, индикатор показывает «сохранено».

## Команды

```bash
npm install && npm run dev          # локально, порт 5173
npm run build                       # сборка
npm run backup                      # снять срез (нужен .env)
npm run restore -- <файл.json>      # восстановить из копии
npx supabase db push --db-url "$SUPABASE_DB_URL"   # накатить миграции
```

Публикация — автоматически по push в `main` (workflow «Публикация на GitHub Pages»).
